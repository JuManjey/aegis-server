# Политика безопасности AEGIS relay (Security Policy)

Это серверная часть (релей/mailbox) продукта AEGIS. Модель доверия —
**zero-trust к самому серверу** (§7.6/§10.9 технического задания):
сервер хранит и передаёт только непрозрачный шифртекст и не должен видеть
plaintext, личности или связь «кто-кому».

## Ответственное раскрытие (coordinated disclosure)

**Не создавайте публичный issue для уязвимостей.** Сообщайте приватно:

- GitHub → **Security → Report a vulnerability** (Security Advisories).

Если вы разворачиваете собственный сервер, проблемы конкретного развёртывания
решает его администратор; уязвимости самого кода — сюда.

Обязательства по срокам, safe harbor и bug bounty — как в клиентском репозитории
(`aegis-client/SECURITY.md`); политика едина для всего продукта.

## Приоритетная область (scope)

- Любой способ, которым сервер получает/раскрывает **plaintext**, ключи или
  метаданные «кто-кому» (нарушение zero-trust §7.6).
- Утечка через логи (должны быть без чувствительных данных), тайминги, размеры.
- Возможность связать `mailbox_id` с личностью/устройством.
- Обход ограничений (cap/TTL, rate limiting) → DoS/переполнение хранилища.
- Уязвимости TURN-провижининга (`GET /v1/turn`), blob-store (`/v1/blob/{id}`).
- Проблемы деплоя: раскрытие портов наружу (должен быть только Onion v3),
  утечка секретов, некорректный TLS/автообновление сертификата (клирнет-режим).

## Криптографические принципы

- **Свою криптографию не пишем** (§1) — аудированные крейты RustCrypto.
- SHA-1 используется **только внутри HMAC** для TURN REST-кредов coturn
  (требование протокола); HMAC-SHA1 остаётся стойким.
